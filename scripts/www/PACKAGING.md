# 打包 APK 与试装指南

应用名：**实验室记录本**
形态：Android APK（组员点一下安装就能用，不需要找文件、不需要开浏览器）

---

## 一、打包前先备好三个东西

| 东西 | 位置 | 说明 |
|---|---|---|
| 手机端单文件 | `lab-notebook/phone/实验记录本.html` | **必须是最新的** |
| 图标 | `lab-notebook/phone/icon/512x512.png` | 已生成好 |
| 应用名 | 实验室记录本 | — |

### 确认手机端是最新的

改过物料库（`presets.js`）或手机端代码后，一定要重新生成：

```
node scripts/build-phone.js
```

**判断是不是最新**：用记事本打开 `实验记录本.html`，搜「单文件版，构建于」，看时间对不对。

---

## 二、PakePlus 打包步骤

1. 打开 PakePlus → **新建应用**
2. **应用名称**：`实验室记录本`
3. **入口类型**：选「本地文件」，指向
   `lab-notebook/phone/实验记录本.html`
4. **图标**：上传 `lab-notebook/phone/icon/512x512.png`
5. **平台**：勾选 **Android**（其他都不勾）
6. 点 **发布 / 打包**
7. 等待完成 → 下载 APK

> PakePlus 的 Android 打包走云端，不需要你本机装 Android SDK。
> 如果卡在"需要登录 / 需要 Token"，按它的提示注册即可。

### 打出来之后先自己装

**不要直接发给组员。** 先装在自己的手机上，按下面的清单验一遍。

---

## 三、自测清单（装完先自己过一遍）

这台手机上依次点一遍，任何一项不对就记下来：

| # | 操作 | 期望结果 |
|---|---|---|
| 1 | 点图标启动 | 2 秒内出现界面，不白屏 |
| 2 | 填工号、姓名、选体系 → 保存 | 跳到"记录"页 |
| 3 | 点一个实验模板 | 自动填好类型、流程、物料分类 |
| 4 | 选料、填用量、保存 | 提示"已保存到手机" |
| 5 | 切到「待传」页 | 显示 1 条待导出 |
| 6 | 点「导出 N 条待传记录」 | 弹出保存位置，选「下载」 |
| 7 | 在文件管理器找到导出的文件 | 文件名形如 `待传记录_U023_20260214_1830.json` |
| 8 | **把这个文件传到电脑** | 用数据线或微信文件传输助手 |
| 9 | 电脑端 →「导入记录」→ 拖入文件 | 能识别出来，显示"可导入 1 条" |
| 10 | 点「导入并扣库存」 | 记录进了台账，库存被扣 |
| 11 | 关闭 App 再打开 | 之前录的记录还在 |
| 12 | 手机调成飞行模式再记一条 | 仍能保存（离线可用） |

**第 8~10 步是整套系统的命门**——手机数据能不能顺利进内网。这一条不通，前面都白搭。

## 四、试装怎么发

先给 **2~3 个人**装，不要全员。

### 发给试装的人

微信直接把 APK 文件发过去，附一句话：

> 这是实验室记录本，先装一下试试。点开文件选「安装」，如果提示"未知来源"就允许一次。
> 装好后帮我按这个清单点一遍，哪里不顺手直接告诉我。

### 要收集的反馈

别问"好用吗"，问具体的：

1. 装的时候卡在哪一步了？（有没有出现"未知来源"提示、能不能装上）
2. 打开后第一眼知道该点什么吗？
3. 选物料时找得到你要用的料吗？找不到的是哪种？
4. 哪一步点了没反应、或者反应不对？
5. 你平时做实验，会在手机上记还是回电脑再记？

第 5 个问题最关键。如果答案是"回电脑再记"，那手机端可能根本不需要，早点发现能省很多事。

---

## 五、试装期之后怎么办

试装期一般 1~2 周。这段时间**不要反复重打包**，攒着一起改。

| 情况 | 处理 |
|---|---|
| 只是名字/字段/流程要改 | 改代码 → `node scripts/build-phone.js` → 重新打包 → 版本号 +1 |
| 物料库要改 | 改 `presets.js` → `build-phone.js` → 重新打包 |
| 组员反馈"根本不用手机" | 停下来重新评估，可能只保留电脑端 |

### 版本号怎么标

自己维护一个明文版本号，方便追溯：

- 打包前在 `phone/index.html` 的 `<title>` 后面加注释，或
- 直接看 `实验记录本.html` 里「单文件版，构建于」那行时间

发给组员时在群里说一句「这是 6 月 12 日版」，出问题时能对上。

## 六、常见打包问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 打包出的 App 打开白屏 | 指向的不是单文件，或依赖没内联 | 确认入口是 `实验记录本.html` 而不是 `index.html` |
| 桌面上图标是默认机器人 | 没上传图标 | 上传 `icon/512x512.png` |
| 装的时候提示"解析包出错" | APK 下载不完整 | 重新下载 |
| 装完点开闪退 | 打包时选了不兼容的架构 | 选 arm64 + armeabi-v7a（兼容老手机） |
| 导出文件找不到 | Android 11+ 存储限制 | App 内导出时会弹保存位置，选「下载」 |
| 组员手机提示"禁止安装" | 系统默认拦截未知来源 | 设置 → 应用 → 允许安装未知应用 → 选微信/文件管理器 |

---

## 七、如果组员连 APK 都不愿装

那说明手机端对你们来说是伪需求。这时候有两个选择：

1. **只保留电脑端** —— 组员在电脑上录，手机只是查看（可以做一个只读的手机版）
2. **改回"传 HTML 文件"** —— 但你已经判断过这条路接受度更低

我的建议是：先按第四节试装 2~3 人。**如果这 3 个人里有 2 个觉得麻烦**，就别推全员了，把精力放在电脑端的可用性上——毕竟数据最终都在内网那台机器上，手机端只是录入的一个入口而已。
